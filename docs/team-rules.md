# Правила роботи в команді (знімок)

Розділ із [`CONTRIBUTING.md`](https://github.com/container-forest/container-forest/blob/course/semester-1/CONTRIBUTING.md) основного репозиторію станом на тег `course/semester-1`. Історію змін див. там.

- Кожен PR перевіряється на [інваріанти безпеки](https://github.com/container-forest/container-forest/blob/course/semester-1/docs/security-invariants.md): порушувати їх не можна в жодному PR.
- Жодних прямих комітів у `main`. Лише PR із зеленим [CI](https://github.com/container-forest/container-forest/blob/course/semester-1/CONTRIBUTING.md#ci), відкритий у `main` (не в гілку іншого PR).
- Рев'ю (рішення команди): кожен PR Бояра В. О., Синенка Д. В. і Денисенко Л. В. мерджиться лише після аппруву Петренка Б. О.; GitHub додає його рев'юером автоматично (`.github/CODEOWNERS`). Свої PR Петренко Б. О. перевіряє сам.
- Проєкт ліцензовано за [Apache License 2.0](https://github.com/container-forest/container-forest/blob/course/semester-1/LICENSE). Надсилаючи PR, ви погоджуєтеся, що ваш внесок ліцензується на тих самих умовах (розділ 5 ліцензії). Код, на який ви не маєте прав, не додавайте; нову залежність перевіряйте на сумісність ліцензії (без GPL і AGPL у коді, що лінкується).
- Коміти за [Conventional Commits](https://www.conventionalcommits.org/): `feat(agent): ...`, `fix(web): ...`.
- **`CONTRIBUTIONS.md`** — кожен веде свій список класів, методів, ієрархій, екранів і обробників для лаб. Оновлюйте разом із PR, а не в кінці семестру. Попередній розподіл класів і екранів між учасниками — у [docs/project-overview.md](project-overview.md#команда).
- Нотатки для ретроспективи з лаби 3 пишіть у `docs/retro/<бібліотека>.md` одразу, поки пам'ятаєте проблеми. Якщо з бібліотекою працює кілька учасників, кожен пише свій розділ у тому самому файлі.
- Документацію оновлюйте в тому самому PR: опис підсистеми — у `docs/design/`, конвенції компонента — у `src/<компонент>/CLAUDE.md`, у кореневий `CLAUDE.md` — лише те, що стосується всього проєкту.
- Архітектурні рішення, про які сперечались (наприклад, «git тягне ЦА, а не агент»), фіксуйте короткими ADR у `docs/adr/`.
- Аналіз аналогів у `docs/project-overview.md` оновлюється на кожному етапі проєкту новим підрозділом з датою; стан на початку розробки не редагується.
