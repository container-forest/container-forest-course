# Ретроспектива: System.CommandLine

- Пакет: `System.CommandLine` 2.0

Кожен учасник, що працював із бібліотекою, пише свій розділ за питаннями з умови лаби 3.

## Петренко Б. О.

### Які задачі розв'язує бібліотека

- Розбір командного рядка CLI `forest` (ADR-0008): дерево команд (`env`, `container`, `stack`, `deployment`, `context`…), аргументи й опції з типами (`Guid`, `int?`, `DateTimeOffset?`, enum), обов'язкові опції, обмеження значень (`on`/`off`).
- Глобальні опції для всіх підкоманд (`--url`, `--token`, `--context`, `-o`) через `Recursive`.
- Довідка (`--help`), `--version`, коди виходу для помилок розбору, скасування команди за Ctrl+C (токен у дії команди).

### Чому саме ця бібліотека

Альтернативи — Spectre.Console.Cli і CommandLineParser. Spectre.Console.Cli будує команди через рефлексію над класами налаштувань, що для NativeAOT вимагає додаткових анотацій. CommandLineParser не має вкладених команд як дерева. System.CommandLine 2.0 — стабільний пакет від Microsoft, сумісний з AOT і без рефлексії: опції й аргументи — звичайні об'єкти, тож команди CLI описані власною ієрархією класів (`ForestCommand` → `EnvironmentCommand` → `StackCommand`).

### Документація

Між бета-версіями й 2.0 API сильно змінився (`SetHandler` → `SetAction`, `InvocationContext` зник, `AddOption` → `Add`, `IsRequired` → `Required`), а більшість прикладів в інтернеті — для бета-версій. Надійним джерелом були документація на learn.microsoft.com для 2.0 і XML-коментарі пакета.

### Проблеми та як їх розв'язали

1. **Застарілі приклади.** Див. вище: API звіряли з XML-документацією пакета.
2. **Тестованість.** Бібліотека пише помилки розбору в `Console`. Дерево команд будується з `CliHost` (потоки виводу, змінні середовища, каталог конфігурації, HTTP-обробник, браузер), а тести передають власні потоки й `InvocationConfiguration`, тож CLI запускається проти ЦА в пам'яті.
3. **Клас `Program` у двох збірках.** Top-level statements CLI створили глобальний `Program`, що конфліктував з `Program` ЦА в інтеграційних тестах; точка входу CLI — явний `ContainerForest.Cli.Program`.

### Плюси й мінуси

Плюси:

- типізовані опції й аргументи, автоматична довідка й помилки розбору;
- рекурсивні глобальні опції;
- без рефлексії, сумісна з NativeAOT.

Мінуси:

- мало актуальних прикладів для 2.0;
- немає вбудованого способу описати команду класом: каркас (`ForestCommand`, `CommandGroup`) довелося писати самим;
- назви значень enum у довідці показуються як є (`Json|Table`), їх доводиться задавати через `HelpName`.

### Що змінили б

Так само: власна ієрархія команд поверх бібліотеки. Інакше: від початку писати тести розбору командного рядка для кожної групи команд, а не лише вибіркові.
