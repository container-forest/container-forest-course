# Ретроспектива: Kiota

- Пакети: `Microsoft.Kiota.Bundle` (рантайм), інструмент `microsoft.openapi.kiota` (генератор, `dotnet-tools.json`)

Кожен учасник, що працював із бібліотекою, пише свій розділ за питаннями з умови лаби 3.

## Петренко Б. О.

### Які задачі розв'язує бібліотека

- Клієнт REST API ЦА для CLI `forest` (ADR-0008): типізовані запити й моделі генеруються із закоміченого OpenAPI-документа ЦА (`scripts/generate-cli-client.sh` → `src/Cli/Api/Generated`), як `schema.gen.ts` для панелі. CI перегенеровує клієнт і падає, якщо закомічений відрізняється.
- Серіалізація моделей у JSON для `forest … -o json` (`KiotaJsonSerializer`).

### Чому саме ця бібліотека

Розглядали NSwag, Refitter (Refit) і ручний клієнт. NSwag розрахований здебільшого на OpenAPI 3.0, а ASP.NET Core 10 генерує 3.1 з nullable-типами як `["string", "null"]`. Refit для NativeAOT довелося б перевіряти окремо. Ручний клієнт не перевіряє CI: DTO тихо розійшлися б із ЦА. Kiota — генератор Microsoft із повною підтримкою OpenAPI 3.1 і NativeAOT.

### Документація

Документація на learn.microsoft.com добре пояснює генерацію й автентифікацію (`IAuthenticationProvider`), гірше — middleware-ланцюжок `HttpClient`: що `KiotaClientFactory.Create()` за замовчуванням вмикає повтори запитів, з'ясувалося лише на живому ЦА.

### Проблеми та як їх розв'язали

1. **Повтори запитів за замовчуванням.** `RetryHandler` тричі повторював відповідь 503 (агент офлайн), зокрема POST деплою; повтор POST міг би поставити другий деплой. Клієнт збирається з обробників за замовчуванням без `RetryHandler` (`ForestApiFactory`).
2. **Помилки лише для описаних статусів.** Згенерований клієнт розбирає problem details тільки для статусів, які перелічує OpenAPI-документ; на 503 він кидав `ApiException` без тексту ЦА, а `AggregateException` з повторами виводився стектрейсом. Власний `ProblemDetailsHandler` перетворює будь-яку невдалу відповідь на `ServerProblemException` з `title`/`detail`, а CLI показує їх і обирає код виходу.
3. **Nullable і mutable моделі.** Усі властивості моделей nullable, навіть обов'язкові в контракті. Команди працюють не з клієнтом, а з адаптером `ForestApi`: він повертає списки замість null, а відсутнє обов'язкове поле перетворює на зрозумілу помилку (`Required`).
4. **Обсяг згенерованого коду.** ~140 файлів на 80 операцій; ендпоінти, яких CLI не викликає (webhook-и, вхід паролем, підтвердження входу CLI), виключені з генерації.

### Плюси й мінуси

Плюси:

- повна підтримка OpenAPI 3.1 і NativeAOT без попереджень обрізання;
- клієнт генерується з того самого документа, що й типи панелі, і CI ловить розбіжність;
- `IAuthenticationProvider` і ланцюжок `DelegatingHandler` легко розширюються.

Мінуси:

- багатослівний код і nullable-моделі вимагають адаптера;
- повтори за замовчуванням небезпечні для неідемпотентних запитів;
- шість пакетів рантайму в бандлі, хоча потрібен лише JSON.

### Що змінили б

Так само: адаптер над згенерованим клієнтом і власний обробник помилок. Інакше: одразу збирати ланцюжок обробників вручну, а не через `KiotaClientFactory.Create()`, і додати до OpenAPI-документа ЦА відповіді 503 для ендпоінтів, що звертаються до агента.
