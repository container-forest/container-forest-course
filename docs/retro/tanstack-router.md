### Які задачі розв'язує бібліотека

- Маршрутизація веб-панелі з файлів (`src/Web/src/routes`): плагін для Vite генерує `routeTree.gen.ts`, і маршрути, параметри та search params типізовані.
- Захист сторінок, що потребують входу: pathless layout `_authed` у `beforeLoad` перевіряє `/api/me` і на 401 перенаправляє на `/login` з адресою повернення.
- Контекст роутера (`queryClient`), через який маршрути завантажують дані заздалегідь (`defaultPreload: "intent"`).

### Чому саме ця бібліотека

Розглядали React Router. Обрали TanStack Router, бо:

- типи шляхів, параметрів і search params перевіряє компілятор, а не лише рантайм;
- search params проходять валідацію схемою (Zod), що зручно для фільтрів таблиць;
- loader'и й `beforeLoad` природно працюють із кешем TanStack Query через контекст роутера.

### Проблеми та як їх розв'язали

1. **Open redirect через `?redirect=`.** Сторінка входу повертає користувача за адресою з search params; абсолютна адреса там дозволила б перенаправити на чужий сайт. Схема `validateSearch` приймає лише шляхи того самого сайту (`/…`, не `//…`), а некоректне значення відкидає (`.catch(undefined)`).
2. **Згенерований файл у репозиторії.** `routeTree.gen.ts` генерує плагін під час `dev`/`build`, але без нього не проходить перевірка типів. Файл комітиться, а CI перевіряє, що після збірки він не змінився.
3. **Devtools у робочій збірці.** Панелі розробника підключено під `import.meta.env.DEV`; перевірено, що в production-бандл вони не потрапляють.

### Проблеми, що виникли

- `redirect` — це шлях разом із search (`location.href`), а не відомий маршрут, тож `navigate({ to })` його не приймає за типами; використали `navigate({ href, replace: true })`. `replace`, щоб «Назад» не повертав на форму входу.
