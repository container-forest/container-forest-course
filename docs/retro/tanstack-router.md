# Ретроспектива: TanStack Router

- Пакети: `@tanstack/react-router`, `@tanstack/router-plugin` (генерація дерева маршрутів для Vite), `@tanstack/react-router-devtools`

Кожен учасник, що працював із бібліотекою, пише свій розділ за питаннями з умови лаби 3.

## Петренко Б. О.

### Які задачі розв'язує бібліотека

- Маршрутизація веб-панелі з файлів (`src/Web/src/routes`): плагін для Vite генерує `routeTree.gen.ts`, і маршрути, параметри та search params типізовані.
- Захист сторінок, що потребують входу: pathless layout `_authed` у `beforeLoad` перевіряє `/api/me` і на 401 перенаправляє на `/login` з адресою повернення.
- Контекст роутера (`queryClient`), через який маршрути завантажують дані заздалегідь (`defaultPreload: "intent"`).

### Чому саме ця бібліотека

Розглядали React Router. Обрали TanStack Router, бо:

- типи шляхів, параметрів і search params перевіряє компілятор, а не лише рантайм;
- search params проходять валідацію схемою (Zod), що зручно для фільтрів таблиць;
- loader'и й `beforeLoad` природно працюють із кешем TanStack Query через контекст роутера.

### Документація

Документація TanStack Router велика й актуальна, а для двох головних задач є готові гайди: автентифіковані маршрути (саме те, що робить `_authed`) і валідація search params. Складніше було з угодами файлової маршрутизації (`__root`, префікс `_` для pathless layout, згенерований `routeTree.gen.ts`): вони розкидані між кількома сторінками, і їх простіше зрозуміти з прикладу в репозиторії бібліотеки.

### Проблеми та як їх розв'язали

1. **Open redirect через `?redirect=`.** Сторінка входу повертає користувача за адресою з search params; абсолютна адреса там дозволила б перенаправити на чужий сайт. Схема `validateSearch` приймає лише шляхи того самого сайту (`/…`, не `//…`), а некоректне значення відкидає (`.catch(undefined)`).
2. **Згенерований файл у репозиторії.** `routeTree.gen.ts` генерує плагін під час `dev`/`build`, але без нього не проходить перевірка типів. Файл комітиться, а CI перевіряє, що після збірки він не змінився.
3. **Devtools у робочій збірці.** Панелі розробника підключено під `import.meta.env.DEV`; перевірено, що в production-бандл вони не потрапляють.

### Плюси й мінуси

Плюси:

- шляхи, параметри й search params перевіряє компілятор: посилання на неіснуючий маршрут не збереться;
- `validateSearch` зі схемою Zod закриває open redirect і стане основою для фільтрів таблиць;
- `beforeLoad` і контекст роутера з `queryClient` дають перевірити вхід до рендеру сторінки, без мигання захищеного вмісту.

Мінуси:

- потрібен плагін Vite і згенерований файл у репозиторії, а CI має перевіряти, що він актуальний;
- типи бібліотеки складні: помилки компілятора в маршрутах важко читати, а довільну адресу повернення доводиться передавати через `href`, а не `to`;
- менша спільнота, ніж у React Router: відповіді частіше шукаються в документації й issues, ніж на StackOverflow.

### Що змінили б

Так само: TanStack Router разом із TanStack Query й схема для кожного search param. Інакше: одразу описати в `CONTRIBUTING.md` угоди файлової маршрутизації з прикладом нового екрана, щоб кожен учасник не розбирався з ними окремо.

## Денисенко Л. В.

### Які задачі розв'язує бібліотека

- Екран `/login` читає перевірений search param `redirect` (`Route.useSearch`) і після входу повертає користувача туди, звідки його відправив `_authed`.
- Перехід після входу й виходу — `useNavigate`.

### Проблеми, що виникли

- `redirect` — це шлях разом із search (`location.href`), а не відомий маршрут, тож `navigate({ to })` його не приймає за типами; використали `navigate({ href, replace: true })`. `replace`, щоб «Назад» не повертав на форму входу.

### Документація, плюси й мінуси, що змінили б

Для екрана входу вистачило гайду про автентифіковані маршрути й готового `validateSearch` у каркасі. Плюс: `redirect` уже перевірений і типізований, `useSearch` повертає його без ручного розбору URL. Мінус: тип `navigate({ to })` приймає лише відомі маршрути, а адреса повернення — довільний шлях із search, тож довелося з'ясувати різницю між `to` і `href`. Наступного разу варто прочитати сторінку про навігацію до того, як писати переходи.
